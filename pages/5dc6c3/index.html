fork原理图：

    由 fork 创建出来的子进程，它首先拷贝一份和父进程一模一样的 PCB控制块，然后设置专属于自己的部分数据，例如 pid，用户栈指针 等。接着把父进程栈中的数据拷贝一份到自己的 TSS 中，这样就会让 fork 出来的子进程拥有和父进程一样的函数调用返回地址，这样当子进程执行的时候，就会返回到和父进程一模一样的 fork 函数调用点继续执行代码。

# Linux011的fork实现流程

# 一、0号进程fork出1号进程

由于我们开启了分页，所以现在每个进程都拥有 4GB(1024*1024*4KB) 的线性地址空间。

但是我们目前只有16MB的内存地址，并且将16MB的线性地址空间与这16MB的物理地址空间一一对应了起来。

又因为在Linux0.11中，所有进程共用同一个页目录表，所以现在所有的进程共用同一个线性地址空间了！！！（可能因为在Linux0.11中限制了进程最大为64MB，最多允许同时存在64个进程，所以一个线性地址空间就够用了）

Linux0.11规划所有进程在同一个线性地址空间下的分布如下所示：

在0号进程执行 fork 之前，线性地址空间的内存布局如下所示：

TSS 是任务状态段,用来保存和恢复进程的上下文。TSS 中的 ss0:esp0 用于作为进程在内核态执行时的堆栈，即 CS寄存器 的值为 GDT表 中0特权级的代码段描述符的时候。
eip 用于在进程切换的时候，切换到当前进程的指令地址（根据 eip 可以跳转到进程上一次被切换时的指令继续执行）。esp 指向进程在用户态执行时的栈顶。ldt 指向当前进程的 ldt表。start_code表示当前进程的代码段起始地址。

    0号进程调用 fork 函数，fork 函数内部调用 int 0x80 中断的一瞬间，会往0号进程的内核栈压入5个值，如图所示：

紧接着在 int 0x80 中断对应的处理程序system_call中会依次压入ds、es、fs、edx、ecx和ebx，用于保存上下文。

    fork的第一步首先是获得一个进程号，然后申请一页物理内存来存放新进程（1号进程）的进程控制块PCB。(为了便于理解，这里线性地址空间低16MB与物理内存一一对应，所以直接在线性地址空间中画图了)

第二步，拷贝父进程（0号进程）的PCB到新进程（1号进程）中，然后新进程初始化独属于新进程自己的数据。

    TSS中的 ss0:esp0 用于作为1号进程在内核态执行时的堆栈，即CS寄存器的值为GDT表中0特权级的代码段描述符的时候。因为在eip中保存了当前进程的返回地址（从父进程继承），所以第一次执行1号进程的时候，会返回到和0号进程同样的位置，就调用一次fork，父子进程返回的都是同一个地方。esp指向进程在用户态执行时的栈顶。ldt指向当前进程的ldt表。

    第三步，为1号进程设置它的LDT表，让其拥有私有的线性地址空间。这里1号进程的ldt中的段描述符指向了线性地址0x4000000处的640KB大小的空间。（实际并未真正申请物理内存，会触发缺页异常！）

    第四步，需要为1号进程设置线性地址空间对应的页目录表和页表，理论上应该每个进程都有属于自己的页目录表，但是在Linux0.11中，所有进程共有同一个页目录表，即所有进程共用同一个线性地址空间。既然如此，就不需要为1号进程设置页目录表0，但是需要为1号进程设置页表(需要申请一页物理内存来存放)，并在页目录表中登记此页表。Linux0.11中是把父进程的页表直接复制到子进程的页表中，这样子进程的页表就设置好了！

    此时，1号进程线性地址空间映射物理内存的地址是和0号进程一样的，但是现在是只读状态，写入的时候会引发缺页中断（挖个坑，后面再补一篇缺页中断的文章）。

    最后一步，在GDT表中设置1号进程的LDT和TSS描述符，把1号进程的状态改为RUNING，然后把1号进程放到task数组进行管理即可！

# 二、1号进程fork出2号进程

1号进程fork出2号进程的流程 和 0号进程fork出1号进程 是差不多的，只有复制页表的时候有细微差别，从原来的复制160项到复制1024项(整张页表)。另外从1号进程开始的fork函数，都会把父进程的页表项修改为只读状态，因为父子进程共享了相同的物理内存区域。
    那为什么0号进程fork出1号进程的时候，0号进程的页表项没有被修改为只读状态？那是因为0号进程是第一个进程呀，0号进程最大，什么都能修改(^_^)！
    从2号进程开始，以后所有的fork执行逻辑都和2号进程一样！

在1号进程执行fork之前，线性地址空间的内存布局如下所示：

1号进程调用fork函数，fork函数内部调用 int 0x80 中断的一瞬间，会往1号进程的内核栈压入5个值，如图所示：

fork的第一步首先是获得一个进程号，然后申请一页物理内存来存放新进程（2号进程）的进程控制块PCB。

第二步，拷贝1号进程的PCB到2号进程中，然后新进程初始化独属于新进程自己的数据。

第三步，为2号进程设置它的LDT表，让其拥有私有的线性地址空间。这里2号进程的ldt中的段描述符指向了线性地址0x8000000处的640KB大小的空间。（实际并未真正申请物理内存，会触发缺页异常！）

第四步，需要为2号进程设置线性地址空间对应的页目录表和页表，理论上应该每个进程都有属于自己的页目录表，但是在Linux0.11中，所有进程共有同一个页目录表，即所有进程共用同一个线性地址空间。既然如此，就不需要为2号进程设置页目录表，但是需要为2号进程设置页表(需要申请一页物理内存来存放)，并在页目录表中登记此页表。

    此时，2号进程线性地址空间映射物理内存的地址是和1号进程一样的，但是现在是只读状态，写入的时候会引发缺页中断。需要注意的是，此时1号进程的页表项也被设置为了只读状态。若其中的一个页表项指向内存页需要进行写操作，则会触发页异常，这样页异常中断处理程序就会为执行写操作的进程分配一页新的空闲页面，从而进行写时复制操作。

    最后一步，在GDT表中设置2号进程的LDT和TSS描述符，把2号进程的状态改为RUNING，然后把2号进程放到task数组进行管理即可！
